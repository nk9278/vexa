# VEXA - PHASE 23 DOCUMENTATION
## CLIENT DELIVERY PLANNER & MONTHLY DELIVERABLES ENGINE

### 1. Overview
Phase 23 introduces the Client Delivery Planner. This module acts as the bridging mechanism between a client's active retainer/package and the actual work generated by the production team. It allows managers to define custom deliverable types, set monthly targets, automatically generate items, track execution progress in real-time, and view an organized calendar schedule.

### 2. Database Modifications
- Safely extended `setup_db.php`:
  - `deliverable_types`: A dictionary table to store agency-specific deliverable formats (e.g., "Instagram Reel", "SEO Blog").
  - `monthly_plans`: Defines the high-level monthly strategy for a specific client, including month, budget, and overall status.
  - `deliverables`: Augmented with `monthly_plan_id` and `deliverable_type_id`. Added `assigned_team_ids` (stored as JSON) to facilitate flat assignment mapping for Phase 23 before a full pivot table expansion if needed in Phase 24 Task Engine.

### 3. Onboarding Integrations
- `includes/onboarding.php` was incrementally updated to inject the new module permissions:
  - Added permissions: `view_deliverables`, `create_deliverables`, `edit_deliverables`, `delete_deliverables`, `manage_deliverable_types`.
  - Intelligently appended to the `Owner`, `Manager`, and `CRM` roles so they are provisioned upon tenant creation.

### 4. Backend APIs (`/api/owner/deliverables/`)
- `types.php`: Handles the creation and safety-checked deletion (ensuring no active deliverables use the type before dropping) of custom deliverable types.
- `plans.php`: Handles the creation of a new monthly plan. Importantly, it features a "Bulk Generate" mechanism. When a manager defines targets (e.g., 4 Reels, 2 Blogs), the API automatically inserts the corresponding empty deliverable records into the database linked to that month's plan.
- `items.php`: Manages granular CRUD operations on specific deliverables (changing status, due dates, removing items, and saving team assignments as JSON arrays).
- **Security Check:** All APIs enforce strict CSRF verification via `verifyCsrfToken($_POST['csrf_token'])` and validate IDOR by restricting `SELECT` / `UPDATE` queries with `company_id`.

### 5. Frontend UI (`/owner/deliverables/`)
- `index.php`: The main Monthly Planner Dashboard. Features dynamic month-selection, top-level agency statistics, and a grid view of active plans highlighting their real-time completion progress bar.
- `types.php`: A clean interface for managing the dictionary of deliverable types with active usage indicators.
- `create_plan.php`: A responsive form allowing the selection of a client, the month, and a dynamic grid of inputs for all active deliverable types to set target quantities.
- `view_plan.php`: The interactive workspace for a specific monthly plan. Features Kanban-style status counters, a progress bar, quick-add inline forms, and a comprehensive data table to update individual deliverable statuses, due dates, and open the Team Assignment modal.
- `calendar.php`: An aggregated timeline view isolating items by their due dates for the selected month, providing managers a quick bird's-eye schedule.

### 6. Security and Quality Control
- **Navigation:** Updated `/owner/includes/sidebar.php` properly without overwriting the file, adding the `Delivery Planner` tab.
- **Validation:** Syntax checks (`php -l`) passed flawlessly.
- **Modularity:** No existing modules were overwritten. The system builds upon the CRM and Team modules implemented in prior phases.

The system is now primed for Phase 24, where these planned deliverables will be broken down into actionable micro-tasks for the production team.
